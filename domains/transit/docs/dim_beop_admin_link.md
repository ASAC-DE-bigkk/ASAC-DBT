# dim_beop_admin_link — 법정동↔행정동 링크 (공통, asac_axes)

- **한 행** = 법정동↔행정동 연계 1쌍 / **grain**: (`beop_dong_code`, `admin_dong_code`) 쌍 유일 / 743행
- **원천**: `bronze_admin_dong_master` 최신 개정, 서울, 집계행 제외
- **왜 필요한가**: 주소 기반 데이터(사업자 주소, 부동산 등)는 대부분 **법정동**으로 오는데, 팀 공통축은 **행정동**이다. 이 테이블이 그 번역 다리.

## 컬럼

| 컬럼 | 설명 |
|---|---|
| `beop_dong_code` / `beop_dong_nm` | 법정동 10자리 코드 / 이름 |
| `admin_dong_code` / `admin_dong` | 행정동 10자리 코드 / 이름 (공통축 키) |
| `gu_code` | 자치구 5자리 |
| `revision_date` | 개정 기준일 |

## 활용 추천

1. **법정동 주소 데이터의 공통축 편입**: 예) commerce의 인허가 주소(법정동) → 이 링크로 행정동 코드 부여 → 전 도메인과 동 단위 조인 가능.
2. **동명만 있는 데이터 매칭**: `beop_dong_nm`으로 이름 매칭 후 코드 획득 (동명 중복 주의 — 구와 함께 매칭).

## ⚠️ 다대다 주의 (중요)

법정동↔행정동은 1:1이 아니다 — **법정동 467개 중 134개가 복수 행정동에 걸치고, 행정동 426개 중 91개가 복수 법정동을 포함**한다.

- 법정동 키로 이 링크에 조인하면 **행이 불어날 수 있다**(fan-out). 집계 전에 반드시 인지할 것.
- 값(매출·건수 등)을 행정동으로 배분해야 하면: ① 대표 행정동 1개 선택(순번 최소 등 규칙 명시), ② 균등 분할(1/n), ③ 면적·인구 가중 — 분석 목적에 따라 선택하고 문서화.
- 단순 "이 법정동이 어느 구인가"는 fan-out 무관(`gu_code`는 쌍 내 동일).
